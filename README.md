# نظام حجز الوجبات 🍽️

موقع إلكتروني متكامل لحجز وجبات **الإفطار والغداء والعشاء**، مبني حسب العرض التقديمي «نظام حجز الوجبات».
يتكوّن من ثلاث واجهات تعمل على قاعدة بيانات واحدة:

| الواجهة | لمن | الرابط |
|---|---|---|
| **واجهة العضو** | الأعضاء من الجوال أو الكمبيوتر | `/` |
| **لوحة المشرف** | المشرف من الكمبيوتر | `/admin` |
| **شاشة الاستلام** | جهاز لوحي ثابت عند نقطة التوزيع | `/kiosk` |

الموقع بالكامل من اليمين لليسار، ومتجاوب مع الجوال، ويمكن تثبيته كتطبيق على الجوال (PWA).

## أولًا: التشغيل خطوة بخطوة

### المتطلبات
- **Node.js الإصدار 22.9 أو أحدث** (قاعدة البيانات SQLite مدمجة فيه، فلا تحتاج لتثبيت قاعدة بيانات منفصلة).

### الخطوات
```bash
# 1) تنزيل المشروع
git clone https://github.com/balushi2001/meal-booking.git
cd meal-booking

# 2) تثبيت المكتبات
npm install

# 3) (اختياري) إضافة بيانات تجريبية: أعضاء ومنيو وحجوزات للتجربة
npm run seed:demo

# 4) تشغيل الموقع
npm start
```
ثم افتح المتصفح على: **http://localhost:3000**

### الحسابات الجاهزة عند أول تشغيل
| الحساب | اسم الدخول (في خانة رقم العضوية) | كلمة المرور |
|---|---|---|
| المشرف | `admin` | `admin12345` |
| شاشة الاستلام | `kiosk` | `kiosk12345` |
| الأعضاء التجريبيون (بعد `seed:demo`) | تظهر أرقامهم في الطرفية مثل `A819` | `12345678` |

> ⚠️ غيّر كلمتي مرور المشرف وشاشة الاستلام فورًا من **لوحة المشرف ← الإعدادات**.
> يمكن أيضًا تحديدهما قبل أول تشغيل عبر المتغيرين `ADMIN_PASSWORD` و`KIOSK_PASSWORD`.

### تشغيل الاختبارات
```bash
npm test
```

## ثانيًا: كيفية العمل — واجهة العضو

### 1. إنشاء حساب (`/register`)
1. يدخل العضو **الاسم الكامل** و**رقم الهاتف (واتساب)** مع رمز الدولة مثل `+968 9123 4567`، ويختار **النادي**، ثم **كلمة المرور** (8 خانات على الأقل) وتأكيدها.
2. إذا كان في أي حقل خطأ تظهر رسالة واضحة تحت الحقل نفسه (مثلًا: رقم الهاتف مسجّل لعضو آخر).
3. عند النجاح يظهر **رقم العضوية** فورًا مع زر «نسخ الرقم».

### 2. توليد رقم العضوية تلقائيًا
- **الحرف الأول من الاسم** يُحوَّل إلى حرف إنجليزي كبير: أحمد ← `A`، سالم ← `S`، مريم ← `M`.
- يليه **ثلاثة أرقام عشوائية غير متكررة**، مثل `527` وليس `557`، فيكون الرقم `A527`.
- إذا كان الرقم مستخدمًا يُعاد التوليد تلقائيًا، ويوجد **قيد فريد في قاعدة البيانات** يمنع التكرار حتى لو سجّل عضوان في اللحظة نفسها.
- سعة كل حرف 720 رقمًا (10×9×8). عند اقتراب الحرف من الامتلاء يظهر تنبيه للمشرف، وعند الامتلاء تُضاف خانة رابعة تلقائيًا.

### 3. تسجيل الدخول (`/login`)
- بـ **رقم العضوية** وكلمة المرور، ولا فرق بين الحروف الكبيرة والصغيرة (`a527` = `A527`).
- **حماية من التخمين:** بعد 5 محاولات خاطئة يُوقف الدخول لهذا الرقم 15 دقيقة.
- **نسيت كلمة المرور أو رقم العضوية؟** يُرسل رمز تحقق إلى واتساب العضو، وبعد التحقق يظهر رقم العضوية ويمكن تعيين كلمة مرور جديدة. ويستطيع المشرف أيضًا إعادة تعيينها.
- تبقى الجلسة مفتوحة على جهاز العضو حتى يسجّل الخروج.

### 4. الصفحة الرئيسية
- الترحيب باسم العضو، ورقم عضويته أعلى الصفحة دائمًا.
- **تنبيه حجز الغد** مع عدّاد تنازلي حتى وقت الإغلاق (11:59 م)، وبعد الحجز يتحول إلى ملخص بما تم حجزه.
- **وجبات اليوم:** حالة كل وجبة بلون وكلمة: تم الاستلام / محجوز / غير محجوز.
- **المستحق:** إجمالي المبالغ غير المدفوعة، ومنه إلى كشف الحساب.
- **شريط التنقل** ثابت أسفل الشاشة: الرئيسية · الحجز · حجوزاتي · حسابي.

### 5. الحجز (ثلاث خطوات)
1. **منيو الغد (`/book`):** بطاقة لكل وجبة فيها النوع والاسم والوصف والسعر. لمس البطاقة يحددها بإطار أخضر وعلامة «تم الاختيار»، ولمسها مرة أخرى يلغي التحديد. يمكن اختيار صنف واحد لكل وجبة. شريط الإجمالي يتحدّث فورًا بعدد الوجبات والمبلغ.
   إذا لم يُنشر المنيو تظهر رسالة «لم يُنشر منيو الغد بعد».
2. **النادي وطريقة الاستلام:** النادي المحفوظ في الحساب يظهر محددًا تلقائيًا ويمكن تغييره، ثم **سفري (بارسل)** أو **الجلوس في النادي** — والاختيار يُطبَّق على كل وجبات ذلك اليوم.
3. **طريقة الدفع والتأكيد:**
   - **الدفع الآن:** تحويل إلى بوابة الدفع. عند النجاح يُثبت الحجز بحالة «مدفوع»، وعند الفشل لا يُثبت الحجز ويعود العضو لاختيار طريقة أخرى.
   - **عند نزول الراتب:** يُثبت الحجز فورًا بحالة «مستحق» ويُضاف المبلغ إلى رصيد العضو، وعند السداد يسجّله المشرف فيتحول إلى «مدفوع».
   - بعد التأكيد تظهر رسالة نجاح، ويظهر الحجز فورًا في «حجوزاتي» وفي أعداد المشرف.

### 6. حجوزاتي وحسابي
- **حجوزاتي (`/my`):** سجل شهري مع التنقل بين الأشهر، وإجمالي المستحق والمدفوع، وحالتان لكل حجز (الاستلام والدفع)، والحجوزات التي أنشأها المشرف تظهر بإشارة «بواسطة المشرف».
- **حسابي (`/account`):** الاسم والهاتف ورقم العضوية، المستحقات والدفعات، تغيير النادي الافتراضي، تغيير كلمة المرور، وتسجيل الخروج.

## ثالثًا: كيفية العمل — لوحة المشرف (`/admin`)

| الصفحة | ماذا تفعل |
|---|---|
| **الرئيسية** | حجوزات الغد (مقسّمة إفطار/غداء/عشاء)، من لم يحجز للغد، استلام اليوم، إجمالي المستحقات، وملخص وجبات الغد للمطبخ مقسّمًا حسب النادي وطريقة الاستلام. |
| **المنيو** | اختيار التاريخ ← إضافة/تعديل/حذف الوجبات. السعر من **قائمة ثابتة 0.500 – 2.000 ر.ع بفارق 100 بيسة**. يمكن إضافة أكثر من صنف للنوع الواحد، و**نسخ منيو يوم سابق** كاملًا. تعديل السعر لا يغيّر الحجوزات السابقة، والوجبة التي عليها حجوزات **تُخفى ولا تُحذف** مع تنبيه بعدد حجوزاتها. |
| **الحجوزات** | كل حجوزات يوم معيّن مع فلترة بالوجبة والنادي والحالة والبحث، تعديل حالة الاستلام يدويًا، وتنزيل ملخص المطبخ Excel. |
| **حجز نيابة عن عضو** | 4 خطوات: البحث عن العضو (بالاسم/الرقم/الهاتف) ← اليوم والوجبة ← طريقة الدفع ← التأكيد. يظهر للعضو كأنه حجزه بنفسه مع إشارة «بواسطة المشرف»، ويُحفظ اسم المشرف ووقت الإنشاء في سجل التدقيق. |
| **الأعضاء** | بحث وفلترة (الكل / عليهم مستحقات / موقوفون). صفحة كل عضو فيها: سجله الشهري، **تسجيل دفعة** (نقدًا أو تحويلًا، وتُقبل الدفعات الجزئية وتُغطّى الحجوزات الأقدم أولًا)، تعديل البيانات، إعادة تعيين كلمة المرور، إيقاف/تفعيل الحساب، وتنزيل تقريره Excel. |
| **المدفوعات** | كل الدفعات المسجّلة في الشهر، وإجمالي المدفوع إلكترونيًا. |
| **التقارير** | ملخص الشهر وتنزيل **ملف Excel لكل الأعضاء** (ورقة لكل عضو + ورقة ملخص، اتجاه من اليمين لليسار). |
| **الإعدادات** | وقت إغلاق الحجز ووقت التذكير، أوقات الوجبات لشاشة الاستلام، قائمة الأندية، السماح بالإلغاء، نص رسالة واتساب، سجل الرسائل، سجل التدقيق، وكلمات المرور. |

## رابعًا: كيفية العمل — شاشة الاستلام (`/kiosk`)

1. على الجهاز اللوحي سجّل الدخول بحساب `kiosk` — هذا الحساب **لا يفتح إلا شاشة الاستلام**.
2. الشاشة تحدد **الوجبة الحالية** تلقائيًا حسب أوقات الوجبات في الإعدادات.
3. العضو يُدخل رقم عضويته (حرف ثم أرقام) ويضغط **تحقق**:
   - **يوجد حجز:** يظهر الاسم والوجبة وحالتها ← يضغط **تأكيد الاستلام** فيُسجَّل وقت الاستلام.
   - **لا يوجد حجز:** تظهر رسالة «لا يوجد حجز مسجل» مع زر رجوع.
   - **رقم خاطئ:** «رقم العضوية غير موجود».
   - **استلام مكرر:** «تم الاستلام الساعة 12:41» — لا تُستلم الوجبة مرتين.
4. تعود الشاشة للبداية تلقائيًا بعد 10 ثوانٍ.

## خامسًا: القواعد الزمنية والمهام التلقائية

| الوقت | ماذا يحدث |
|---|---|
| مسبقًا | المشرف ينشر منيو اليوم التالي. |
| طوال اليوم | الحجز مفتوح لوجبات الغد. |
| **9:00 م** | رسالة واتساب تلقائية لكل عضو لم يحجز أي وجبة للغد (لا تُرسل إذا لم يُنشر المنيو). |
| **11:59 م** | يُغلق حجز الغد تلقائيًا ويصبح العدد نهائيًا للمطبخ، و**الخادم يرفض أي حجز بعد الإغلاق** حتى لو كانت الصفحة مفتوحة. |
| نهاية اليوم | كل حجز لم يُستلم يتحول إلى «لم يُستلم» ويبقى مبلغه مستحقًا. |

جميع الأوقات قابلة للتعديل من الإعدادات، وتُحسب بتوقيت مسقط (`Asia/Muscat`).

**حالات الحجز:** محجوز ← تم الاستلام / لم يُستلم / ملغى (الإلغاء قبل الإغلاق فقط، وإذا فعّله المشرف من الإعدادات).
**حالات الدفع:** الدفع الآن ← مدفوع · عند نزول الراتب ← مستحق ← مدفوع (عندما يسجّل المشرف السداد).

## سادسًا: الربط بالخدمات الخارجية

انسخ الملف `.env.example` إلى `.env` واضبط القيم، أو مرّرها كمتغيرات بيئة عند التشغيل.

### واتساب (WhatsApp Business API)
بدون إعداد، تُسجَّل الرسائل في **الإعدادات ← آخر الرسائل** وفي الطرفية فقط (مناسب للتجربة). للإرسال الفعلي:
```
WHATSAPP_TOKEN=...                 # رمز الوصول من Meta
WHATSAPP_PHONE_NUMBER_ID=...       # معرّف رقم الواتساب التجاري
WHATSAPP_REMINDER_TEMPLATE=...     # اسم قالب التذكير المعتمد من Meta (متغيراته: الاسم، التاريخ، وقت الإغلاق، الرابط)
```
> رسائل التذكير التي تبدأها المنشأة تتطلب **قالبًا توافق عليه Meta مسبقًا**.

### بوابة الدفع
النظام يأتي ببوابة **تجريبية** (محاكاة نجاح/فشل الدفع) حتى يمكن تجربة المسار كاملًا.
لربط بوابة حقيقية (مثل ثواني Thawani أو OmanNet أو Stripe) عدّل الملف `src/lib/payment.js`:
الدالة `createCheckout` تُنشئ جلسة الدفع وتعيد رابط التحويل، ونتيجة الدفع تُعالج في المسار `POST /pay/gateway/:token` داخل `src/routes/member.js`.

## سابعًا: النشر على خادم

```bash
NODE_ENV=production \
PORT=3000 \
SESSION_SECRET="سلسلة-عشوائية-طويلة" \
COOKIE_SECURE=1 \
SITE_URL="https://meals.example.com" \
npm start
```
- استخدم HTTPS (مثلًا خلف Nginx أو Caddy) واضبط `COOKIE_SECURE=1`.
- قاعدة البيانات ملف واحد في `data/meals.db` — **خذ منه نسخة احتياطية دوريًا**.
- المهام المجدولة تعمل داخل الخادم نفسه، فيجب أن يبقى الخادم يعمل باستمرار (مثلًا عبر `pm2` أو `systemd`).

## البنية التقنية

```
src/
  server.js            نقطة التشغيل
  db.js                قاعدة البيانات (SQLite) والجداول والإعدادات
  seed-demo.js         بيانات تجريبية
  routes/
    auth.js            التسجيل والدخول واستعادة الحساب
    member.js          واجهة العضو والحجز والدفع
    admin.js           لوحة المشرف
    kiosk.js           شاشة الاستلام
  lib/
    memberNo.js        توليد رقم العضوية
    bookings.js        قواعد الحجز
    ledger.js          المستحقات وتوزيع الدفعات
    scheduler.js       المهام المجدولة (التذكير، الإغلاق، لم يُستلم)
    whatsapp.js        إرسال واتساب
    payment.js         بوابة الدفع
    reports.js         تقارير Excel
    time.js, format.js أدوات التاريخ والتنسيق
views/                 صفحات EJS
public/                التنسيق والسكربتات وملفات PWA
test/                  اختبارات القواعد الأساسية
```

**البيانات الأساسية:** `users` (الأعضاء والأدوار) · `meals` (الوجبات) · `bookings` (الحجوزات مع السعر وقت الحجز) · `payments` (المدفوعات) · `audit_log` (سجل التدقيق) · `messages` (سجل رسائل واتساب).

**الأمان:** كلمات مرور مشفّرة (bcrypt)، صلاحيات حسب الدور (عضو / مشرف / شاشة استلام)، حماية من تخمين كلمة المرور، وسجل تدقيق لكل تعديل يجريه المشرف.
